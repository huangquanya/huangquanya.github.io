## 01 通用最佳实践：写代码的基本功

### 01.1 始终使用类型注解

这是我最想强调的一点。类型注解不是给机器看的，是给人看的，更是给未来的自己看的。

```python
# 推荐 ✅
class User(BaseModel):
    id: int
    name: str
    email: str
    is_active: bool = True

# 不推荐 ❌
class User(BaseModel):
    id = 0
    name = ''
    email = ''
    is_active = True
```

**为什么**：
- IDE能给出更好的代码补全
- 类型检查器能提前发现问题
- 其他人读代码更容易理解
- 重构时更安全

### 01.2 合理设置默认值

这个坑我见过太多人踩了，尤其是处理列表和字典的时候：

```python
# 错误示范：共享默认值 ❌
class BadUser(BaseModel):
    tags: list[str] = []  # 所有实例共享同一个列表！
    metadata: dict = {}   # 同样的问题

u1 = BadUser()
u1.tags.append('python')

u2 = BadUser()
print(u2.tags)  # 输出: ['python']，惊不惊喜？意不意外？

# 正确示范：使用default_factory ✅
class GoodUser(BaseModel):
    tags: list[str] = Field(default_factory=list)
    metadata: dict = Field(default_factory=dict)
    
u1 = GoodUser()
u1.tags.append('python')

u2 = GoodUser()
print(u2.tags)  # 输出: []，这才对嘛
```

**经验之谈**：只要是可变对象（list、dict、set等），一律用`default_factory`。

### 01.3 使用 Field 提供元数据

别只用Field设默认值，它的元数据功能也很强大：

```python
from pydantic import BaseModel, Field
from pydantic.networks import EmailStr, HttpUrl

class User(BaseModel):
    id: int = Field(..., description="用户唯一标识")
    name: str = Field(
        ..., 
        min_length=1, 
        max_length=50,
        description="用户姓名",
        examples=["张三", "李四"]
    )
    email: EmailStr = Field(
        ..., 
        description="用户邮箱地址",
        examples=["user@example.com"]
    )
    website: HttpUrl = Field(
        None, 
        description="个人网站"
    )
```

**好处**：
- 生成API文档时自动包含描述
- examples可以用于测试
- 开发时有更好的提示

### 01.4 妥善处理验证错误

千万别让ValidationError直接抛给前端用户：

```python
from pydantic import BaseModel, ValidationError
from fastapi import FastAPI, HTTPException

app = FastAPI()

class User(BaseModel):
    id: int
    name: str
    email: str

@app.post("/users/")
async def create_user(user_data: dict):
    try:
        user = User.model_validate(user_data)
        # 保存到数据库...
        return {"message": "用户创建成功", "user": user.model_dump()}
    except ValidationError as e:
        # 记录详细错误信息
        print(f"Validation error: {e.errors()}")
        
        # 给用户友好的错误提示
        raise HTTPException(
            status_code=422,
            detail={
                "error": "数据格式错误",
                "message": "请检查输入的数据格式",
                "details": e.errors()  # 开发环境下可以返回详细错误
            }
        )
```

**生产环境建议**：
- 开发环境：返回详细的ValidationError
- 生产环境：只返回友好的错误信息，具体错误记日志

## 02 AI应用最佳实践：经验之谈

### 02.1 API请求模型

在AI应用中，API请求模型要特别注意范围限制：

```python
from typing import List, Optional, Literal
from pydantic import BaseModel, Field

class ChatMessage(BaseModel):
    role: Literal['user', 'assistant', 'system']
    content: str

class ChatRequest(BaseModel):
    model: Literal['gpt-4', 'gpt-3.5-turbo', 'claude-3']
    messages: List[ChatMessage]
    
    # 严格的范围限制很重要
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)
    max_tokens: Optional[int] = Field(default=1000, gt=0, le=4096)
    top_p: float = Field(default=1.0, ge=0.0, le=1.0)
    frequency_penalty: float = Field(default=0.0, ge=-2.0, le=2.0)
    presence_penalty: float = Field(default=0.0, ge=-2.0, le=2.0)
    
    # 防止意外的额外字段
    model_config = ConfigDict(extra='forbid')
```

**为什么严格**：
- 防止传错参数（比如temperature传成10）
- API调用成本控制
- 避免因为参数错误导致的意外行为

### 02.2 配置管理

AI应用的配置通常很复杂，建议分层管理：

```python
from pydantic import BaseModel, ConfigDict
from typing import Optional

class LLMConfig(BaseModel):
    """LLM配置"""
    model_config = ConfigDict(frozen=True)  # 配置应该是不可变的
    
    provider: str = 'openai'
    model: str = 'gpt-4'
    temperature: float = 0.7
    max_tokens: int = 1000
    timeout: int = 30
    
class APIConfig(BaseModel):
    """API配置"""
    model_config = ConfigDict(frozen=True)
    
    openai_api_key: str
    anthropic_api_key: Optional[str] = None
    base_url: str = 'https://api.openai.com/v1'

class AppConfig(BaseModel):
    """应用配置"""
    model_config = ConfigDict(frozen=True, extra='forbid')
    
    environment: str = 'development'
    debug: bool = False
    
    llm: LLMConfig = LLMConfig()
    api: APIConfig
```

**最佳实践**：
- 配置应该是不可变的（frozen=True）
- 禁止额外字段（extra='forbid'），防止拼写错误
- 分层管理，便于维护

### 02.3 提示词模板

提示词模板要能验证变量完整性：

```python
from typing import Dict
from pydantic import BaseModel, field_validator
import string

class PromptTemplate(BaseModel):
    name: str
    template: str
    variables: Dict[str, str]
    
    def format_safe(self, **kwargs) -> str:
        """安全格式化，检查所有变量都已提供"""
        missing = set(self.variables) - set(kwargs)
        if missing:
            raise ValueError(f'缺少必需的变量: {missing}')
        
        # 使用string.Template，更安全
        template = string.Template(self.template)
        return template.substitute(**kwargs)

# 使用
template = PromptTemplate(
    name='文章摘要',
    template='总结以下文章为${length}字：\n\n${content}',
    variables={
        'length': '字数限制',
        'content': '文章内容'
    }
)

# 这会报错，提示缺少变量
try:
    result = template.format_safe(length='200')
except ValueError as e:
    print(e)  # 缺少必需的变量: {'content'}
```

**好处**：
- 避免运行时才发现变量缺失
- 代码更可靠
- 易于调试

### 02.4 数据解析

从LLM解析数据时，要有容错机制：

```python
from pydantic import BaseModel
import json
from typing import Optional

class LLMResponse(BaseModel):
    content: str
    finish_reason: str
    
    @classmethod
    def from_json(cls, json_str: str) -> 'LLMResponse':
        """从JSON字符串解析，有容错"""
        try:
            data = json.loads(json_str)
            return cls.model_validate(data)
        except (json.JSONDecodeError, ValueError) as e:
            # 如果解析失败，返回默认值
            print(f"解析失败: {e}")
            return cls(content=json_str, finish_reason='parse_error')

# 使用
response_text = '{"content": "你好", "finish_reason": "stop"}'
response = LLMResponse.from_json(response_text)
print(response.content)
```

**容错很重要**：
- LLM可能返回格式不正确的JSON
- 网络问题可能导致响应不完整
- 有容错机制，程序更稳定

## 03 性能优化：让代码跑得更快

### 03.1 批量验证用TypeAdapter

处理大量数据时，TypeAdapter比逐个验证更快：

```python
from pydantic import TypeAdapter

# 假设有大量用户数据
users_data = [{'id': i, 'name': f'User{i}'} for i in range(1000)]

# 使用TypeAdapter批量验证
type_adapter = TypeAdapter(User)
users = type_adapter.validate_python(users_data)

# 比这样快：
# users = [User.model_validate(data) for data in users_data]
```

### 03.2 已验证数据跳过验证

如果数据已经验证过，可以跳过验证提升性能：

```python
# 已经验证过的数据
user = User.model_validate({'id': 1, 'name': 'John'})

# 复制时跳过验证
user_copy = User.model_construct(
    id=user.id,
    name=user.name
)
```

**注意**：`model_construct`不进行验证，只在确定数据安全时使用。

### 03.3 避免不必要的配置

有些配置会影响性能：

```python
# 严格模式会慢一些
model_config = ConfigDict(strict=True)  # 只在需要时开启

# from_attributes=True会增加开销
model_config = ConfigDict(from_attributes=True)  # 只在需要时使用
```

## 04 与其他框架集成

### 04.1 FastAPI集成

FastAPI底层就是基于Pydantic的：

```python
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class Item(BaseModel):
    name: str = Field(..., min_length=1, max_length=100)
    price: float = Field(..., gt=0)
    description: str = Field(None, max_length=500)

@app.post("/items/")
async def create_item(item: Item):
    # FastAPI自动使用Pydantic进行验证
    # item已经是验证过的Item实例
    return {"item": item.model_dump()}
```

**优势**：
- 自动验证请求数据
- 自动生成API文档
- 类型安全的响应

## 05 错误处理最佳实践

### 05.1 集中处理ValidationError

```python
from pydantic import ValidationError
import logging

logger = logging.getLogger(__name__)

def safe_validate(model_class, data):
    """安全验证，捕获错误"""
    try:
        return model_class.model_validate(data)
    except ValidationError as e:
        logger.error(f"Validation error for {model_class.__name__}: {e.errors()}")
        return None

# 使用
user = safe_validate(User, user_data)
if user is None:
    # 处理错误
    pass
```

### 05.2 提供友好的错误信息

```python
from pydantic import ValidationError

def format_validation_error(error: ValidationError) -> str:
    """格式化验证错误为用户友好的消息"""
    messages = []
    for err in error.errors():
        field = '.'.join(str(loc) for loc in err['loc'])
        msg = err['msg']
        messages.append(f"{field}: {msg}")
    return '; '.join(messages)

# 使用
try:
    user = User.model_validate(invalid_data)
except ValidationError as e:
    user_friendly_msg = format_validation_error(e)
    print(f"输入有误: {user_friendly_msg}")
```

## 06 代码组织最佳实践

### 06.1 模型分组

```python
# models/
# ├── __init__.py
# ├── base.py      # 基础模型
# ├── user.py      # 用户相关模型
# ├── product.py   # 产品相关模型
# └── api.py       # API请求/响应模型

# models/base.py
from pydantic import BaseModel, ConfigDict

class TimestampedModel(BaseModel):
    """带时间戳的基础模型"""
    model_config = ConfigDict(from_attributes=True)
    
    id: int
    created_at: datetime
    updated_at: Optional[datetime] = None

# models/user.py
from .base import TimestampedModel

class User(TimestampedModel):
    name: str
    email: str
```

### 06.2 使用TypeAdapter处理动态类型

```python
from pydantic import TypeAdapter
from typing import Union

# 动态决定使用哪个模型
UserOrProduct = Union[User, Product]
type_adapter = TypeAdapter(UserOrProduct)

# 根据数据自动选择正确的模型
data = {'name': 'John', 'email': 'john@example.com'}
obj = type_adapter.validate_python(data)
print(type(obj))  # <class '__main__.User'>
```

✅ **框架集成**：充分利用FastAPI、LangChain等
