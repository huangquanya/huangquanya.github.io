## 01 ConfigDict：新一代配置方式

Pydantic v2引入了ConfigDict，这是推荐的配置方式。我们先来看看怎么用：

```python
from pydantic import BaseModel, ConfigDict

class Model(BaseModel):
    model_config = ConfigDict(
        str_max_length=100,      # 字符串最大长度
        extra='ignore',           # 忽略额外字段
        frozen=True,              # 冻结模型（不可变）
        from_attributes=True,     # 允许从对象属性创建
        populate_by_name=True,    # 允许按字段名填充
        arbitrary_types_allowed=True,  # 允许任意类型
    )
    name: str
    age: int
```

ConfigDict其实就是个字典，但提供了更好的类型提示和自动补全。

### 为什么要用ConfigDict？

以前Pydantic v1是用内部类Config来配置的：

```python
# 旧方式（Pydantic v1）
class Model(BaseModel):
    name: str
    
    class Config:
        extra = 'ignore'
        frozen = True
```

这种方式有几个问题：
1. 不是标准的Python语法，IDE可能无法识别
2. 配置项没有类型提示
3. 继承时配置合并逻辑复杂

ConfigDict解决了这些问题，用起来更Pythonic。

## 02 常用配置选项详解

### 2.1 字符串处理相关

```python
from pydantic import BaseModel, ConfigDict

class User(BaseModel):
    model_config = ConfigDict(
        str_max_length=50,       # 最大长度
        str_min_length=1,        # 最小长度
        str_strip_whitespace=True,  # 去除首尾空白
        str_to_lower=True,       # 转小写
        # str_to_upper=True,     # 转大写
    )
    
    username: str
    email: str

# 测试
user = User(username='  JohnDoe  ', email='JOHN@EXAMPLE.COM')
print(user.username)  # 输出: johndoe
print(user.email)     # 输出: john@example.com
```

这些配置在处理用户输入时特别有用，能自动清理数据。

### 2.2 额外字段处理

```python
from pydantic import BaseModel, ConfigDict

# ignore：忽略额外字段（默认）
class ModelIgnore(BaseModel):
    model_config = ConfigDict(extra='ignore')
    name: str

m1 = ModelIgnore(name='John', age=25)  # age被忽略
print(m1.model_dump())  # {'name': 'John'}

# forbid：禁止额外字段
class ModelForbid(BaseModel):
    model_config = ConfigDict(extra='forbid')
    name: str

try:
    ModelForbid(name='John', age=25)  # 报错！
except Exception as e:
    print('禁止额外字段:', e)

# allow：允许额外字段
class ModelAllow(BaseModel):
    model_config = ConfigDict(extra='allow')
    name: str

m3 = ModelAllow(name='John', age=25)
print(m3.model_dump())  # {'name': 'John', 'age': 25}
```

**实际应用场景**：
- API请求模型：建议用`forbid`，能捕获拼写错误
- 数据库模型：建议用`ignore`，避免字段不匹配
- 动态配置模型：建议用`allow`，需要灵活性

### 2.3 模型冻结

```python
from pydantic import BaseModel, ConfigDict

class FrozenModel(BaseModel):
    model_config = ConfigDict(frozen=True)
    name: str
    age: int

user = FrozenModel(name='John', age=25)

# 以下操作都会报错
try:
    user.name = 'Jane'  # 报错：模型已冻结
except Exception as e:
    print('不能修改冻结模型:', e)

try:
    user.age = 30
except Exception as e:
    print('不能修改冻结模型:', e)
```

冻结模型的好处：
- ✅ 线程安全
- ✅ 不可变性，减少bug
- ✅ 可以作为字典的键
- ✅ 适合用作配置对象

### 2.4 从属性创建

```python
from pydantic import BaseModel, ConfigDict

class User(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    
    id: int
    name: str
    email: str

# 假设有一个ORM对象
class ORMUser:
    def __init__(self):
        self.id = 1
        self.name = 'John'
        self.email = 'john@example.com'

orm_user = ORMUser()
user = User.model_validate(orm_user)  # 从ORM对象创建
print(user.name)  # 输出: John

# 也可以用于SQLAlchemy、Django等ORM
```

这个功能在集成数据库时特别有用，不用手动转换对象。

### 2.5 其他常用配置

```python
from pydantic import BaseModel, ConfigDict

class Model(BaseModel):
    model_config = ConfigDict(
        # 赋值时验证（默认False）
        validate_assignment=True,
        
        # 允许任意类型（慎用）
        arbitrary_types_allowed=True,
        
        # 按字段名填充（支持别名）
        populate_by_name=True,
        
        # 严格模式
        strict=True,
        
        # 数字约束
        ser_json_timedelta='iso8601',  # timedelta序列化格式
        ser_json_bytes='utf8',         # bytes序列化格式
    )
    name: str
    age: int
```

## 03 使用类参数（推荐）

Python 3.12+支持在类定义中直接使用配置参数：

```python
from pydantic import BaseModel

class Model(BaseModel, frozen=True):
    a: str
    b: int

# 静态类型检查器能识别这些参数
```

这种方式的优点：
- ✅ 更Pythonic
- ✅ IDE支持更好
- ✅ 类型检查器能识别

但局限性：
- ❌ 只能配置部分选项
- ❌ Python 3.12+才支持

## 04 配置继承

配置是可以继承和覆盖的：

```python
from pydantic import BaseModel, ConfigDict

class Parent(BaseModel):
    model_config = ConfigDict(
        extra='allow',
        str_to_lower=False
    )

class Child(Parent):
    model_config = ConfigDict(
        str_to_lower=True  # 覆盖父类配置
    )
    x: str

m = Child(x='FOO', y='bar')
print(m.model_dump())  
# 结果: {'x': 'foo', 'y': 'bar'}
# 配置合并: extra='allow'（继承）, str_to_lower=True（覆盖）
```

**继承规则**：
1. 子类配置会覆盖父类配置
2. 字典类型的配置会深度合并
3. 大多数配置项是覆盖而不是合并

## 06 实战：复杂配置示例

来看一个实际项目中的配置：

```python
from typing import Optional
from pydantic import BaseModel, ConfigDict, Field
from datetime import datetime

class BaseModelConfig:
    """基础模型配置"""
    return {
        'from_attributes': True,
        'populate_by_name': True,
        'str_strip_whitespace': True,
        'str_min_length': 1,
        'extra': 'forbid',  # 生产环境建议禁止额外字段
        'arbitrary_types_allowed': True,
    }

class TimestampedModel(BaseModel):
    """带时间戳的基础模型"""
    model_config = ConfigDict(**BaseModelConfig.return)
    
    id: int
    created_at: datetime = Field(default_factory=datetime.now)
    updated_at: Optional[datetime] = None

class User(TimestampedModel):
    """用户模型"""
    model_config = ConfigDict(
        **BaseModelConfig.return,
        'frozen': True,  # 用户信息不可变
    )
    
    username: str = Field(..., min_length=3, max_length=50)
    email: str = Field(..., description='用户邮箱')
    is_active: bool = Field(default=True)
    
    class Config:
        # 兼容旧版本
        pass

class Product(TimestampedModel):
    """产品模型"""
    model_config = ConfigDict(
        **BaseModelConfig.return,
        'frozen': False,  # 产品信息可以修改
    )
    
    name: str
    price: float = Field(..., gt=0)
    description: Optional[str] = None
```

## 07 性能考虑

配置会影响性能：

1. **strict=True**：会进行严格类型检查，稍微慢一点
2. **from_attributes=True**：增加属性访问开销
3. **validate_assignment=True**：每次赋值都验证
4. **frozen=True**：创建不可变对象有额外开销

建议：
- 开发环境可以开启更多检查
- 生产环境根据需求调整
- 性能关键路径可以适当放宽配置

## 总结一下

Pydantic配置的核心：
- ✅ **ConfigDict**：推荐的配置方式
- ✅ **extra**：控制额外字段（ignore/forbid/allow）
- ✅ **frozen**：是否冻结模型
- ✅ **from_attributes**：从对象创建
- ✅ **validate_assignment**：赋值时验证
- ✅ 继承和覆盖：灵活组织配置

选择合适的配置能让代码更安全、更易维护。
