说实话，很多人用Pydantic就只知道定义个类继承BaseModel，然后写几个字段。其实BaseModel里藏着不少好东西，我刚开始用的时候也是用了好几个月才发现，原来还能这么玩。

上周在做一个用户系统，需要频繁地在字典和模型之间转换，还要做深拷贝，各种操作搞得挺头大。后来仔细翻了翻Pydantic的文档，才发现BaseModel自带了这么多实用方法，简直是懒人福音。

## 01 BaseModel基础：不只是数据容器

所有Pydantic模型都继承自BaseModel，这个基类可不像普通的Python类那么简单。

```python
from pydantic import BaseModel

class ModelName(BaseModel):
    field1: type1
    field2: type2 = default_value  # 可选：默认值
```

**模型定义规则**：
- 字段使用类型注解
- 可以设置默认值
- 支持所有Python标准类型和容器类型

看起来简单，但BaseModel在背后做了很多工作：类型验证、自动转换、错误处理、序列化等等。你只管定义结构，其他的交给Pydantic。

## 02 模型方法：那些年我错过的神器

这是我最想强调的部分。BaseModel自带的方法，用好了能省不少事。

### model_validate()：从字典创建实例

```python
class User(BaseModel):
    id: int
    name: str
    email: str

# 从字典创建
user_data = {'id': 1, 'name': '张三', 'email': 'zhangsan@example.com'}
user = User.model_validate(user_data)
print(user.name)  # 输出: 张三
```

以前我都是手动解包：`User(**user_data)`，现在用`model_validate()`更语义化，也更安全。

### model_validate_json()：从JSON字符串创建

```python
json_str = '{"id": 2, "name": "李四", "email": "lisi@example.com"}'
user = User.model_validate_json(json_str)
print(user.name)  # 输出: 李四
```

这个在处理API响应时特别有用。直接从JSON字符串转成模型，不用先`json.loads()`再手动创建。

### model_dump()：转换为字典

```python
user = User(id=3, name='王五', email='wangwu@example.com')
user_dict = user.model_dump()
print(user_dict)
# 输出: {'id': 3, 'name': '王五', 'email': 'wangwu@example.com'}
```

需要把模型转回字典时特别方便，比如要存数据库或者传给其他API。

### model_dump_json()：转换为JSON字符串

```python
json_str = user.model_dump_json()
print(json_str)
# 输出: {"id":3,"name":"王五","email":"wangwu@example.com"}
```

一步到位转JSON，比`json.dumps(user.dict())`优雅多了。

### model_copy()：复制实例

```python
user1 = User(id=1, name='张三', email='zhangsan@example.com')
user2 = user1.model_copy()
user2.name = '李四'

print(user1.name)  # 输出: 张三（原对象不变）
print(user2.name)  # 输出: 李四
```

需要深拷贝的时候特别有用。普通的赋值只是引用，修改一个会影响另一个，`model_copy()`是真正的复制。

### model_construct()：不验证直接创建

```python
# 不进行验证直接创建
user = User.model_construct(id='not_an_int', name=123)
print(user.id)    # 输出: not_an_int（还是字符串）
print(user.name)  # 输出: 123（还是整数）
```

**注意**：这个方法不会做类型验证！只在特殊情况下使用，比如你确定数据已经验证过了，想跳过验证提升性能。

我之前在处理一批已经验证过的数据时，用这个方法性能提升了差不多30%。但一定要小心使用，别把未验证的数据塞进去。

## 03 支持的类型：比你想象的多

Pydantic支持的类型比我最初以为的要多得多，不只是基础的int、str这些。

### 基础类型

```python
class BasicTypes(BaseModel):
    integer: int
    string: str
    floating: float
    boolean: bool
    bytes_data: bytes
    complex_num: complex  # 复数
```

### 日期时间类型

```python
from datetime import datetime, date, time, timedelta

class DateTimeTypes(BaseModel):
    created_at: datetime
    birth_date: date
    meeting_time: time
    duration: timedelta

# 自动转换字符串为日期时间
dt = DateTimeTypes(
    created_at='2023-01-15 10:30:00',
    birth_date='1990-05-20',
    meeting_time='14:30:00',
    duration='2 days 3:30:00'
)
```

这个真的太好用了！以前处理日期时间转换总是各种`strptime`，格式不对就报错。现在Pydantic自动帮你搞定，格式不对会给出明确的错误信息。

### 容器类型

```python
from typing import List, Dict, Set, Tuple, FrozenSet

class ContainerTypes(BaseModel):
    tags: List[str]
    scores: Dict[str, int]
    unique_ids: Set[int]
    coordinates: Tuple[float, float]
    frozen_items: FrozenSet[str]
```

### 可选类型

```python
from typing import Optional

class OptionalTypes(BaseModel):
    # Python 3.10+ 推荐这种写法
    nickname: str | None = None
    # 传统写法
    description: Optional[str] = None
```

### 网络类型

```python
from pydantic.networks import EmailStr, HttpUrl, IPvAnyAddress

class NetworkTypes(BaseModel):
    email: EmailStr
    website: HttpUrl
    ip_address: IPvAnyAddress

# 会自动验证格式
try:
    data = NetworkTypes(
        email='not-an-email',
        website='not-a-url',
        ip_address='999.999.999.999'
    )
except Exception as e:
    print(e)  # 会给出具体的验证错误信息
```

网络类型的验证特别实用，不用自己写正则表达式来验证邮箱、URL格式了。

## 04 实战：批量处理API响应

讲个实际的例子。我之前做的一个项目需要批量处理用户数据：

```python
from typing import List
from pydantic import BaseModel, Field
from datetime import datetime

class User(BaseModel):
    id: int
    username: str
    email: str
    created_at: datetime
    is_active: bool = True

class ApiResponse(BaseModel):
    users: List[User]
    total: int
    page: int

# 模拟API响应数据
api_data = {
    'users': [
        {
            'id': 1,
            'username': 'alice',
            'email': 'alice@example.com',
            'created_at': '2023-01-15 10:00:00',
            'is_active': True
        },
        {
            'id': 2,
            'username': 'bob',
            'email': 'bob@example.com',
            'created_at': '2023-02-20 14:30:00',
            # is_active没传，会用默认值True
        }
    ],
    'total': 100,
    'page': 1
}

# 一键转换
response = ApiResponse.model_validate(api_data)

# 访问数据
for user in response.users:
    print(f'{user.username}: {user.email}')
    # 自动类型转换：created_at已经是datetime对象了
    print(f'  注册时间: {user.created_at.strftime("%Y-%m-%d")}')

# 转回JSON
json_str = response.model_dump_json(indent=2)
print(json_str)
```

看到了吗？整个转换过程就一行代码`ApiResponse.model_validate(api_data)`。日期时间自动转换，缺省字段用默认值，类型验证自动完成。以前要写多少代码才能实现这些功能啊。

## 05 性能小贴士

我踩过的一些坑：

1. **批量创建用`model_validate`**
   ```python
   # 推荐
   users = [User.model_validate(data) for data in data_list]
   
   # 或用TypeAdapter（性能更好）
   from pydantic import TypeAdapter
   type_adapter = TypeAdapter(User)
   users = type_adapter.validate_python(data_list)
   ```

2. **已验证数据用`model_construct`**
   ```python
   # 如果数据已经验证过，可以用这个跳过验证
   user = User.model_construct(id=1, name='John')
   ```

3. **避免不必要的验证**
   在性能敏感的循环里，如果能确定数据类型，可以适当用`model_construct`。

## 06 与其他工具的对比

有人问我，Pydantic和dataclass有什么区别？

```python
from dataclasses import dataclass

@dataclass
class DataClassUser:
    id: int
    name: str

# 不会验证！
user = DataClassUser(id='not_an_int', name=123)  # 不会报错！

from pydantic import BaseModel

class PydanticUser(BaseModel):
    id: int
    name: str

# 会验证并报错
try:
    user = PydanticUser(id='not_an_int', name=123)
except Exception as e:
    print(e)  # ValidationError
```

dataclass只管定义，不管验证。Pydantic的核心价值就是验证和转换。
